# Patch design decisions

## Positioning

A launch page for an approachable builder product: AI coding tools, developer utilities, small browser extensions and component businesses. The visual system is reusable even when the buyer replaces the fictional product and demos.

The supplied CodeForge and Agent references inform the continuous page frame, shared section boundaries and product-first composition. Patch uses an original bracket mark, warm citrus palette, editorial copy and a different section sequence. No reference source code, brand, images or product claims are included.

## Frame and hierarchy

The 1,248px page frame anchors one shared grid. Narrow outer rails and registration marks make boundaries visible without surrounding every piece of content with another card. Hero columns use 5/7; the workspace and use-case sections use 4/8. The feature matrix switches from 8/4 to three equal cells. Pricing uses two joined columns and one comparison ledger.

Section headings place small numbered labels opposite large headlines. Every section has its own composition: a workspace, a dotted measuring surface, a file tree, physical keycaps, overlapping appearance cards, a request card, a collected-ideas app, a pricing ledger and the final bracket study.

At laptop widths, the hero copy sits above a wide workspace. Tablet sections collapse selectively; phones retain shared borders and readable copy while product controls stay usable. Horizontal scrolling is confined to code excerpts.

## Color and type

Chalk `#fafaf7`, ink `#202520`, citrus `#dceb99` and graphite `#252c24`. Citrus marks the emphasized headline, selected workflow step and primary actions. Olive provides quieter accent text. Graphite grounds the code editor.

Geist handles headlines and interfaces; Geist Mono supplies coordinates, labels and code. Large headlines use restrained negative tracking. Small mono labels are secondary annotations rather than primary reading text. The main content and interface have a complete graphite appearance, with the same hierarchy and purposeful contrast.

## Visual depth and motion

Most depth comes from borders, spacing and dark/light contrast. Shadows appear only where a surface is conceptually raised: editor, preview card, keycaps and product studies. The highlighted hero phrase has a small rotation, repeated in the appearance cards and closing mark. Motion is limited to hover feedback, resizing and anchor movement. Reduced-motion settings remove transitions and smooth scrolling.

## Product honesty

Every demo control corresponds to a local action. There is no artificial generation delay or false AI response. Prepared examples visibly change code and output, offer usable component exports, and make their local nature clear. Prices and plan features are illustrative; a review dialog shows totals until a buyer configures actual destinations.
