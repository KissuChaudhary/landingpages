# Patch design decisions

## Positioning

A launch page for an approachable builder product: AI coding tools, developer utilities, small browser extensions and component businesses. The visual system is reusable even when the buyer replaces the fictional product and demos.

The supplied CodeForge and Agent references inform the continuous page frame, shared section boundaries and product-first composition. Patch uses an original bracket mark, warm citrus palette, editorial copy and a different section sequence. No reference source code, brand, images or product claims are included.

## Frame and hierarchy

The 1,248px page frame anchors one shared grid. Continuous outer rails connect at actual section boundaries, with small plus marks centered on each rail intersection. The marks are anchored to the borders rather than repeating at arbitrary intervals. Hero columns use 5/7. Workspace, workflow, use cases and FAQ share the same 4/8 division. The feature matrix switches from 8/4 to three equal cells. Pricing uses three joined columns and one comparison ledger. The Builder column has a quiet accent rule and surface tint; the other plans retain equal spacing and aligned actions.

The navigation is 72px tall on desktop and 64px on phones. Each of the eight main sections has one restrained text badge above its heading, using the same mono type, border, spacing and corner radius. Feature subheadings do not repeat it. Shared content gutters align headings and section content. Product visuals sit directly in their grid cells: the main editor is flush, the collected-ideas app is one joined list, and the workflow request is plain large text. The closing action is one ink-colored field with a larger centered headline, two matching actions and a faint cropped bracket mark.

At laptop widths, the hero copy sits above a wide workspace. Tablet sections collapse selectively; all three pricing plans stack below 1,000px. Phones retain shared borders and readable copy while product controls stay usable. Horizontal scrolling is confined to code excerpts.

## Color and type

Chalk `#fafaf7`, ink `#202520`, citrus `#dceb99` and graphite `#252c24`. Citrus marks the emphasized headline, selected workflow step and primary actions. Olive provides quieter accent text. Graphite grounds the code editor.

Geist handles headlines and interfaces; Geist Mono supplies code, badges and file labels. Five shared roles govern the page: 40px section titles (32px on phones), 24px feature headings, 16px body copy, 14px controls and secondary copy, and 12px labels. The hero headline, prices and closing headline have their own display sizes. The closing headline scales from 40px on phones to 64px on desktop. Product screens retain a small, consistent internal hierarchy. No reading text is below 12px.

Primary actions share a 48px height. The navigation uses compact 44px actions; editor tabs and tools use 40px controls. Pricing actions have a restrained width rather than stretching across their columns. On phones, editor copy/export tools move into the header to keep every control accessible at 320px. The complete graphite appearance follows the same hierarchy and spacing.

## Visual depth and motion

Most depth comes from borders, spacing and dark/light contrast. The hero editor has a restrained shadow; keycaps have a physical edge. Real product controls and output screens retain their own boundaries, while redundant wrappers are removed. The highlighted hero phrase and appearance samples have small rotations. Motion is limited to hover feedback, resizing and anchor movement. Reduced-motion settings remove transitions and smooth scrolling.

## Product honesty

Every demo control corresponds to a local action. There is no artificial generation delay or false AI response. Prepared examples visibly change code and output, offer usable component exports, and make their local nature clear. Prices and plan features are illustrative; until a buyer sets checkout links, the free plan opens the workspace and paid plans start an email.
